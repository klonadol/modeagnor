# ADR-0002: Хост-авторитетное исполнение

- **Статус:** Accepted
- **Дата:** 2026-11-02
- **Область:** Multiplayer / Runtime / Security

## Контекст

Агнор должен одинаково работать в одиночной игре и мультиплеере. Память, решения, навигация и действия NPC должны быть едиными для всех участников мира. Клиентские компьютеры подключённых игроков не должны выполнять обязательные вычисления ИИ.

## Решение

Хост Minecraft является авторитетной стороной:
- в одиночной игре это интегрированный сервер;
- в мультиплеере это dedicated server.

На хосте выполняются Character Runtime, обработка событий, очереди гномиков, хранение памяти, вызовы провайдеров, выбор/валидация действий и изменение мира.

Клиенты выполняют UI, рендеринг, визуальную интерполяцию, локальное воспроизведение аудио и отправку проверяемых запросов.

LLM, embedding и TTS могут быть локальными на машине хоста, облачными или доступны на отдельной машине через API. Это внешний выбор конфигурации, а не изменение модели исполнения Агнора.

## Последствия

- Секреты и приватные данные остаются на сервере.
- Состояния и действия синхронизируются через versioned network DTO.
- Каждый серверный обработчик проверяет отправителя и права.
- Сетевой callback не изменяет мир напрямую: изменение планируется в безопасном server-thread контексте.
- Отказ внешнего API не должен останавливать игровой сервер.

## Проверка

**Частично подтверждено bootstrap:** integrated/dedicated и адресный probe двух offline dev UUID, restart marker проверены в [отчёте 004](../reports/2026-11-04-004-phase-0-client-network.md). Это не проверка приватности будущих диалогов/памяти или серверных pose/действий. Эти контракты проверяются с соответствующими функциями по ROADMAP; online authentication пока не подтверждена.
