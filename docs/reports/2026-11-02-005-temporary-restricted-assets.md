# Отчёт 005: Временные dev-only модели с обязательной заменой

- **Дата:** 2026-11-02
- **Статус:** Done (требования и документация обновлены; runtime-механизм реестра не реализован)
- **Ветка:** `main`
- **Связанные ADR:** ADR-0008
- **Связанные этапы:** Фазы 0–4; release gate Фазы 10

## 1. Цель и исходное требование

Упростить разработку небольшой команды (один человек и ИИ): если подходящей модели с ясными правами пока нет, не блокировать техническую работу. Разрешить использовать локальную копию модели с неизвестными/ограниченными правами как временный материал закрытого прототипирования, при условии обязательной фиксации и замены до финального релиза. Если источник предоставляет прямую ссылку на скачивание, предпочитать её ручным обходным процессам.

## 2. Принятое правило

- Допускается только локальное внутреннее dev-only использование; ассет не коммитится, не включается в JAR, публичные/передаваемые Content Packs, CI artifacts, релизные архивы и сетевую синхронизацию.
- Для каждого файла требуется запись в Asset Replacement Register со статусом `TEMPORARY_RESTRICTED`.
- Запись включает ID/название, локальный путь или file ID, исходную страницу, прямую download URL (если доступна), автора/источник, дату получения, SHA-256, известные условия, статус прав, причину временного использования, ответственного и план/статус замены.
- Перед релизом каждый временный ассет заменяется на разрешённый или удаляется. Незакрытые записи блокируют релиз.
- Нераспространение не гарантирует законность локального использования; сохраняется остаточный риск, который нельзя представлять как юридическое разрешение.
- Прямые ссылки на скачивание используются, если они доступны и безопасны. Не обходить paywall, авторизацию, DRM или технические ограничения; скачанные исполняемые файлы не запускать, архивы проверять и распаковывать изолированно.

## 4. Проверки и ограничения

- Изменения внесены в существующую ветку `main`; новая ветка и PR не создавались.
- Документация фиксирует процесс, но канонический Markdown Asset Replacement Register создан в `docs/assets/ASSET_REPLACEMENT_REGISTER.md`; автоматическая проверка релизной сборки и блокировка CI **НЕ РЕАЛИЗОВАНЫ**.
- Юридическая допустимость конкретного файла не проверялась и не выводится из факта локального использования.
- Никакие модельные файлы в репозиторий не загружались.
- Реальный download flow и безопасность конкретных источников в рамках этой задачи не тестировались.

## 5. Следующий практический шаг

При первом использовании временной модели внести запись в [Asset Replacement Register](../assets/ASSET_REPLACEMENT_REGISTER.md) до импорта файла. Позже добавить автоматическую release-проверку, которая отклоняет пакет при наличии `TEMPORARY_RESTRICTED` или `REPLACEMENT_REQUIRED`.
